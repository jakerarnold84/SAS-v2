# summitaudiencesegments.com — Build Handoff

## What's in this folder

- `home.html` · `platform.html` · `data.html` · `thiic.html` · `about.html` — five static pages, each fully self-contained.
- `styles.css` — single source of truth for design tokens, components, and responsive rules.
- `assets/` — pink icon PNG (used as nav logo + favicon) and white horizontal logo (kept in reserve).
- `Spec.html` — long-form build spec with token table, type scale, component conventions, and per-page section sequence.
- `home-print.html` — print-optimized variant of home for PDF export.

## Build instructions for the AI builder

**Reproduce these five pages visually 1:1.** The HTML/CSS in this folder is the source of truth. You may translate to a framework of your choice (Next.js, Astro, plain HTML, etc.), but the rendered output must match these mocks pixel-for-pixel at 1280px+ widths and reflow gracefully below.

**Hard rules:**
1. **Do not paraphrase, edit, abbreviate, or expand any copy.** Every word, number, kicker label, and punctuation choice is locked. If something reads odd, flag for review — do not change it.
2. **Use the exact color tokens.** `#EB0557` coral · `#FFD83A` yellow · `#00FFFF` cyan · `#0A0A0C` canvas · `#111114` surface · `rgba(255,255,255,0.08)` borders. See `styles.css` for the full set.
3. **Use Inter + JetBrains Mono only.** Load via Google Fonts (already wired in the HTML `<head>`). All numerals use JetBrains Mono with `font-variant-numeric: tabular-nums`.
4. **Yellow phrase underline** is the `linear-gradient(180deg, transparent 0, transparent 70%, var(--c-yellow) 70%, var(--c-yellow) 92%, transparent 92%)` rule wrapped on a single phrase per H1/H2 (`.y-under` class). Reuse the rule; do not change the percentages.
5. **Section alternation** is hard-locked: default canvas → `--alt` background → canvas → alt … across every page. Every section sets its `background-color` explicitly. Never inherit.
6. **Footer + nav + status-compliance ribbon** are identical across all five pages.

**Routing:**
- `/` → home
- `/platform` → platform (linked from footer as "Audience Explorer")
- `/data` → data
- `/thiic` → thiic
- `/about` → about
- `/contact`, `/privacy`, `/terms`, `/summit-do-not-sell` — wire utility pages with the same nav + footer chrome.

**Forms:** All CTAs are `mailto:info@summitaudiencesegments.com` in the mock. Replace with a real form + submission endpoint of your choice (HubSpot, Formspree, custom backend) — pop a confirmation modal on submit.

**Hosting:** Deploy to a `v2.` subdomain or sandbox first. Visual + content QA before any production swap.

**Performance targets:** LCP < 2s, no render-blocking scripts, font-display: swap, critical CSS inlined where possible.

**Mobile nav:** Below 1024px the desktop center-nav is hidden. Build a hamburger drawer with the same five links + "Sign in" + "Get in touch" CTA.

**Assets you'll need from us:**
- Real founder photos (currently placeholder initials in team cards)
- Brand-approved DSP partner logos (currently single-letter placeholder chips on the Platform page)

## Questions

Email `info@summitaudiencesegments.com` before changing any copy or visual treatment.

    <p class="body" style="max-width:920px;margin:0 auto 36px;text-align:center;">THIIC is Summit's proprietary identity exchange protocol. Two parties — typically Summit and a licensed partner — exchange hashed identifiers to find overlap between their respective data, without either side transmitting raw PII and without a third-party vendor sitting between them.</p>
    <div class="grid grid-3">
      <div class="card"><span class="card__kicker">01 · No Middleware</span><p class="card__body">LiveRamp, Snowflake clean rooms, AWS clean rooms — all require your data to enter the vendor's environment. <b>THIIC is bilateral. No vendor.</b></p></div>
      <div class="card"><span class="card__kicker">02 · No Per-Record Fees</span><p class="card__body">Identity vendors charge per-match fees that compound at scale. <b>THIIC has zero per-transaction fees.</b></p></div>
      <div class="card"><span class="card__kicker">03 · No Holding-Co Ownership</span><p class="card__body">Identity infrastructure increasingly owned by a single agency conglomerate. <b>THIIC is privately held, healthcare-specific, structurally independent.</b></p></div>
      <div class="card"><span class="card__kicker">04 · Bilateral Key Derivation</span><p class="card__body">Both parties contribute key material. Neither side can unilaterally decrypt. <b>No privileged operator — not even Summit.</b></p></div>
      <div class="card"><span class="card__kicker">05 · Built for Healthcare</span><p class="card__body">HIPAA Safe Harbor, BAA flow-down, state laws (MHMDA, CMIA, CPA, etc.). <b>Purpose-built, not retrofitted.</b></p></div>
      <div class="card"><span class="card__kicker">06 · Standard Primitives</span><p class="card__body">SHA-256, HKDF-SHA256, AES-256-GCM, Ed25519. All FIPS 140-2. All RFCs. <b>No novel cryptography.</b></p></div>

    <p class="body" style="max-width:920px;margin:0 auto 36px;text-align:center;">The protocol runs in eight cryptographic steps. The first five happen on the sender side, the next two move bilaterally, and the final step lands on the recipient side.</p>
    <div class="steps">
      <div class="step"><div class="step__header"><span class="step__num">01</span><span class="step__role step__role--sender">SENDER</span></div><div class="step__name">NORMALIZE</div><div class="step__desc">Identifiers normalized — phone to E.164, email lowercased.</div></div>
      <div class="step"><div class="step__header"><span class="step__num">02</span><span class="step__role step__role--sender">SENDER</span></div><div class="step__name">HASH</div><div class="step__desc">Each identifier hashed with SHA-256, client-side.</div></div>
      <div class="step"><div class="step__header"><span class="step__num">03</span><span class="step__role step__role--bilateral">BILATERAL</span></div><div class="step__name">DERIVE</div><div class="step__desc">HKDF-SHA256 derives a key from both parties' master material.</div></div>
      <div class="step"><div class="step__header"><span class="step__num">04</span><span class="step__role step__role--sender">SENDER</span></div><div class="step__name">WRAP</div><div class="step__desc">Hashes encrypted with AES-256-GCM.</div></div>
      <div class="step"><div class="step__header"><span class="step__num">05</span><span class="step__role step__role--sender">SENDER</span></div><div class="step__name">SIGN</div><div class="step__desc">Ed25519 signs the bundle metadata.</div></div>
      <div class="step"><div class="step__header"><span class="step__num">06</span><span class="step__role step__role--bilateral">BILATERAL</span></div><div class="step__name">TRANSMIT</div><div class="step__desc">Bundle transmitted over mTLS or pre-signed S3.</div></div>
